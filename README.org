#+title: agent-shell-cockpit

A workspace dashboard for [[https://github.com/xenodium/agent-shell][agent-shell]]: Git worktrees, ordinary context files,
reusable instructions, and the sessions working with them.

Cockpit keeps prompts in your hands. Write in Org, Markdown, or agent-shell's
normal input, link files, and add your own comments. There is no request
composer or automatic context extraction. Instruction adapters only produce
references and the short bootstrap needed to read them.

* Requirements and installation

- Emacs 29.1 or later.
- agent-shell 0.75.1+, magit-section 4.0+, transient 0.7+.
- Git for local worktree operations.
- Evil and nerd-icons are optional. Full Magit is neither required nor loaded
  by Cockpit. The optional Org-roam integration must be explicitly loaded.

Install the package with its dependencies, or add this checkout to =load-path=:

#+begin_src emacs-lisp
(use-package agent-shell-cockpit
  :load-path "/path/to/agent-shell-cockpit"
  :commands agent-shell-cockpit
  :bind ("C-c m" . agent-shell-cockpit)
  :custom
  (agent-shell-cockpit-enable-standalone-sessions t))
#+end_src

For Straight users, replace =:load-path= with:

#+begin_src emacs-lisp
:straight (:type git :host github :repo "to-bak/agent-shell-cockpit")
#+end_src

No global keys or window layout are installed by the package itself.
Use =M-x customize-group RET agent-shell-cockpit= for settings.

* Everyday workflow

1. Open =M-x agent-shell-cockpit=. Press =w= to create a workspace.
2. Open it with =RET=. Add a worktree with =+=: choose a source Git repository,
   then a new branch, existing branch, or detached checkout.
3. Press =c= to create a context file, or =e= to choose an existing one. These
   are ordinary files: organize them, write prompts, and link other material
   using your normal editing tools.
4. Press =s= to select instruction IDs with completion, then choose an
   agent. With no instructions selected, the agent starts normally. Selected
   instructions become editable initial input; Cockpit does not submit them.
5. Return to Cockpit with =q= from the agent's Cockpit navigation mode.
   Agent rows show working, attention, and history states. =RET= visits a live
   agent or resumes a recorded session when its configuration is available.
6. On a worktree, =RET= opens Dired (or your configured worktree opener).
7. Stop agents before archiving with =A=. Archived workspaces remain available
   through the dashboard's =l= menu; =R= restores an archived workspace.

Enable =agent-shell-cockpit-enable-standalone-sessions= to expose dashboard =S=.
It asks for a working directory and starts an agent without creating a workspace.
Standalone sessions have no Cockpit-persisted history; agent-shell manages its
own transcripts and native session storage.

* Declarative reusable instructions

Declare the catalog in Emacs configuration. Each instruction has a stable ID,
a title, and a source. Only literals and references are supported:

#+begin_src emacs-lisp
(setq agent-shell-cockpit-instructions
      '((concise :title "Concise responses"
                 :source (literal "Keep your final response concise."))
        (review :title "Code review"
                :source (file "~/instructions/review.md"))
        (manifest :title "AI Manifest"
                  :source (org-roam "dfac4c1b-f48b-4f6b-b55e-cb98f43d4168"))))

(setq agent-shell-cockpit-default-instructions '(cockpit))
#+end_src

=literal= emits its configured string. =file= emits an absolute path and checks
that it exists and is readable; it never copies file contents. =org-id= emits
the ID and its current file location, using Org's ID index. A missing source
or unloaded adapter produces an error before launching or inserting anything.

Launch selection uses =completing-read-multiple=: enter comma-separated IDs.
Titles and source types appear as annotations. Remove the prefilled selection
to start without instructions. Duplicate selections are emitted only once.
The built-in =cockpit= literal describes the actual workspace layout and is
available only for workspace launches.

=M-x agent-shell-cockpit-insert-instruction= inserts selected literals and
references at point. You can add comments and edit the result before sending.
=M-x agent-shell-cockpit-visit-instruction= opens the authoritative source when
its adapter supports visiting. Instructions live wherever you declare them;
Cockpit does not create or discover instruction files in workspaces.

** Explicitly loaded Org-roam integration

The bundled integration module must be loaded explicitly:

#+begin_src emacs-lisp
(require 'agent-shell-cockpit-org-roam)
#+end_src

Core Cockpit never loads this module. Org-roam must be installed to use its
adapter; it is not a core package dependency. The adapter uses the configured
=org-roam-directory= and emits one short navigation bootstrap followed by the
selected =id:= references. It explains exact =:ID:= lookup, file-level IDs,
relative file links, and following relevant links. It does not fetch node
contents or expand a graph into the prompt. Missing nodes are reported by the
agent during lookup; visiting from Emacs resolves them through Org-roam.

** Writing an adapter

A custom adapter needs one callback returning a reference string. It can also
supply a bootstrap and a command for visiting the source:

#+begin_src emacs-lisp
(defun my-handbook-reference (source _workspace)
  (format "https://docs.example.org/handbook/%s" (cadr source)))

(agent-shell-cockpit-register-instruction-adapter
 'handbook
 :reference #'my-handbook-reference
 :bootstrap "Read the selected handbook pages before acting.")

(setq agent-shell-cockpit-instructions
      '((review :title "Review policy" :source (handbook "reviews"))))
#+end_src

The API contract is intentionally small:

- =:reference= is required. It receives =(SOURCE WORKSPACE)=, where SOURCE is
  the entire source list, such as =(handbook "reviews")=. WORKSPACE is the
  workspace record or nil for standalone agents and insertion commands.
  Return a nonempty locator/reference string, never copied source contents.
- =:bootstrap= is optional: a string or function of WORKSPACE returning text
  or nil. It appears once per selected adapter, before all selected items.
- =:visit= is optional: a function receiving =(SOURCE WORKSPACE)= which visits
  the authoritative source.
- Registering an existing type replaces its adapter. Use
  =agent-shell-cockpit-unregister-instruction-adapter= to remove it.
- =literal= is reserved. There is no delivery-mode switch or discovery API.

Callbacks are trusted Emacs configuration. Adapter code controls how to
format its own references; the package cannot inspect the semantic meaning
of arbitrary callback text. Built-in source adapters never copy file/node
contents. The agent needs access to the referenced locations.

| Archives  | R / D     | Restore / delete archive            |

Automatic agent previews are configurable with
=agent-shell-cockpit-agent-preview-behavior=: =delayed=, =manual=, or =off=.
Cockpit preserves view position and folding on refresh. Preview windows use
=display-buffer= and respect user display rules.

Worktrees are flat rows containing the name. A warning dot marks uncommitted
changes (including untracked files); an ellipsis means checking, and a question
mark means status is unavailable. Checks run asynchronously with a five-second
cache. Missing and archived worktrees are labelled. Use your preferred Git
tools from the worktree for review.

The fixed header retains the workspace title and location while scrolling.
Native agent actions include steering and renaming the live buffer. Renaming
uses agent-shell's buffer rename command; it does not rename the agent's stored
conversation title.

Use =C-u RET= on a history row to choose how much history to display when
resuming. =agent-shell-cockpit-session-restore-verbosity= can be =ask=, =minimal=,
=last=, =first-last=, or =full=; its default =nil= inherits agent-shell's setting.
This controls display, not the agent's memory; backend capabilities determine
which restore modes agent-shell can use.

The opener defaults to Dired and remains configurable:

#+begin_src emacs-lisp
(setq agent-shell-cockpit-worktree-open-function #'dired)
(setq agent-shell-cockpit-repository-source-function #'project-prompt-project-dir)
#+end_src

* Storage

#+begin_example
workspace/
  worktrees/               Independent linked Git worktrees
  context/                 User-owned context and prompts
  .agent-shell-cockpit/     Cockpit-owned workspace metadata
#+end_example

New workspaces use =agent-shell-cockpit-worktrees-directory-name=, defaulting
to =worktrees=. This directory is recorded in metadata so subsequent
customization does not change existing workspace paths.

Metadata schema 4 uses a =worktrees= collection. There is no migration,
old-setting alias, legacy skill registry, or experimental composer support.
Older experimental metadata is reported as unsupported and is never silently
converted. Existing source/context files remain on disk. The explicit repair
command backs up and rebuilds metadata; it does not recover historical sessions
or worktree ownership/retention records.

Metadata writes are atomic, use a cooperative lock, and reject stale records.
After a crash, a leftover =workspace.json.write-lock= requires inspection
before manual removal.

* Worktree lifecycle

Cockpit distinguishes owned worktrees from discovered directories. Discovered
worktrees must be explicitly adopted before Cockpit will remove them.

Archive/removal refuses dirty worktrees, including untracked and ignored
files, locked worktrees, modified visiting buffers, and live agents working
inside the affected directory. =P= explicitly moves selected untracked or
ignored files into workspace preservation storage before archive.

Before removing an owned worktree, Cockpit retains its exact commit and task
base under =refs/cockpit/= in the source repository. Archive/restore operations
record progress for recovery after interruption. Restore recreates detached
worktrees at those exact commits and restores preserved files without
replacing existing files. It does not switch back to a branch that may have
advanced elsewhere.

Source repositories must remain available at their recorded local paths.
Archive and restore require the same filesystem. Remote worktrees and
submodule worktrees are not supported. Retention refs are not automatically
pruned when an archive is deleted.

Native reload/fork commands invoked through Cockpit retain session association.
Commands invoked outside Cockpit are not globally advised.

* Development and release checks

#+begin_src sh
make check                  # ERT, native integration, compile, Checkdoc, install smoke
make optional-integration   # Real Evil and optional Org-roam integration
make lint                   # Requires package-lint on load-path
#+end_src

The Makefile discovers required dependencies in =~/.emacs.d/straight/build=.
Set =STRAIGHT_BUILD= for another package directory, or =EXTRA_LOAD_PATH= for
explicit =-L= arguments. Tests use temporary workspaces and do not launch paid
agent sessions. The install smoke test builds a package tarball, installs it
in isolation, and exercises autoloads in a fresh Emacs process.

CI targets Emacs 29.1 and 31.1. Local checks do not replace a graphical
walkthrough or testing every minimum dependency combination. MELPA inclusion
also involves maintainer review and evidence of real use; see
[[https://github.com/melpa/melpa/blob/master/CONTRIBUTING.org][MELPA's contribution guidelines]].

The source is divided into metadata storage, workspace paths, Git operations,
archive/restore lifecycle, native agent-shell compatibility, sessions,
declarative instructions/optional Org-roam, shared UI, and the three dashboard views.
